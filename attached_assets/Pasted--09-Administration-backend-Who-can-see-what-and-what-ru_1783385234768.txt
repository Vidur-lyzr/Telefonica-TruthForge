# 09 · Administration (backend)
### Who can see what, and what runs on a schedule

> Inherits FOUNDATION + File 01. Where the four access profiles and the confidentiality model are managed, and where recurring documents are scheduled. Access is the intersection of *who you are* and *how sensitive the content is* — enforced at the index, never by the LLM.

---

## 1. The job

Let Telefónica run the platform themselves: register users, assign profiles, manage permissions by area and confidentiality, and schedule the recurring documents — all without a vendor. Self-sufficiency is scored; this page is a big part of it.

---

## 2. The four profiles (from the RFP)

| Profile | Scope |
|---|---|
| **Superadmin** | full backend + full workspace |
| **Admin** | all/parts of backend — metadata, Brand Room, access-control (profiles can be unified) |
| **Editor** | total/partial workspace — Documentation+agent (generate), KPIs, Planning |
| **Audit** | read-only trail of who did what (uploaded/modified/consulted) |

Profiles can be added/unified. Each user also belongs to an **area target** — Comunicación / Marca / Gabinete — and subgroups within.

---

## 3. Access = area × confidentiality (the model)

```
┌─ Access model ────────────────────────────────────────────────────────┐
│  USER axis        →  area/profile (Entra ID groups)                    │
│  DOCUMENT axis    →  confidentiality (public/private/confidential)      │
│                       from Microsoft sensitivity labels                 │
│  ACCESS = intersection, applied at retrieval (early-binding)           │
│  the agent never sees a chunk outside the user's scope                 │
└───────────────────────────────────────────────────────────────────────┘
```

The admin manages the *left* side (users → areas/profiles). The *right* side (confidentiality) is inherited from the document's label, not set here. The screen should make this legible — "permissions here + labels from Microsoft = what each person sees."

---

## 4. User & permission management

```
┌─ Users ───────────────────────────────────────────────────────────────┐
│  Vidur R.      Comunicación · Editor        [ edit ] [ ⋯ ]            │
│  Carlos M.     Finance DE · Admin+Docs       confidential ✓            │
│  Ana R.        Marca · Editor                                          │
│  + register user                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

Register/unsubscribe, grant/remove permissions, assign area + confidentiality tier. Changes take effect at the next retrieval — no reindex needed (permissions are a query-time filter, not baked into the data). Show a small "effective access" preview so an admin can see what a user *would* see before saving.

---

## 5. Scheduled documents (content automation)

The admin side of Generate's scheduled mode:
```
┌─ Scheduled documents ─────────────────────────────────────────────────┐
│  Weekly activity summary   Mon 08:00 · ES · owner Comms · → review     │
│  10-day forecast           Fri 16:00 · ES/DE · owner Planning         │
│  Quarterly results deck    on close · owner Finance · → review         │
│  + schedule document                                                   │
└───────────────────────────────────────────────────────────────────────┘
```

Define template · sources/queries · frequency · language · owner · **review folder**. On trigger the agent generates on-brand with cited fresh data → lands in the owner's review folder (never auto-publishes) → owner approves in the Canvas. The human gate is structural.

---

## 6. States & guardrails

- **Over-permissioning warning** — granting confidential access surfaces a confirm ("this exposes Finance-DE confidential to this user").
- **Orphaned schedule** — if a scheduled doc's source is removed, flag it rather than silently failing.
- **Audit view** — every permission change and every scheduled run is logged and viewable by the Audit profile.

---

## 7. Why this page matters

It proves the platform is *theirs to run* — permissions, profiles, and automation managed internally — and it operationalizes the exact access model the RFP specifies: area × confidentiality, enforced at the index, inheriting Microsoft labels. The "supplier dependency after implementation" score lives here.
