PC2 · Access Rights and Taxonomy / Tagging
Access rights (access control)
Access = intersection of two axes, applied at the index/retrieval (early-binding), never by the agent:
1. User axis → area/profile (Communication/Brand/Cabinet + subgroups), from Entra ID groups.
2. Document axis → confidentiality level (public/private/confidential) + group, from Microsoft sensitivity
labels (Purview/MIP) inherited from the source.
Confirmed in the RFP (permissions by profile + “confidentiality comes from Microsoft”). The agent/LLM never
decides or filters: even if retrieval finds a chunk, if the user doesn’t have permission it doesn’t enter the context.
Requires the taxonomy/tagging exercise (to confirm what exists today).
Taxonomy / tagging (as configuration, not as code)
Taxonomy in 2 layers: deterministic (what the document *is*: market/brand/owner/confidentiality/validity) +
derived (what it *says*: Plan axes, topics, entities — the layer that changes with strategy).
• Tags don’t live in the code: they are metadata versioned as configuration, applied after embedding.
Embeddings are agnostic to the taxonomy (calculated once) → re-tagging does not require re-embedding.
• From a governance panel, the strategy is edited → this triggers a back-end re-tagging of existing data (4

steps: editing → mapping table → assisted zero-shot re-classification → human validation), without re-
ingestion, without re-embedding, without redeployment, without IT.

• Anchor: *“changing the strategy = a governance operation, not a technical project”* (RFI Decisions 02 and
04; addresses RFP K2).
Detail in pc2-access-rights-y-taxonomia.
